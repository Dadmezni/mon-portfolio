1. L’idée en une image : des coordonnées pour le sens

Une ville est décrite par 2 nombres (latitude, longitude). Deux villes proches ont des coordonnées proches. Un embedding fait la même chose pour un texte, mais avec des centaines de nombres, et c’est le sens qui est « proche » ou « loin ».

Ville
2 nombres, un lieu sur la carte.
Phrase
384, 768, 1536… nombres, un point dans l’« espace du sens ».

6. Mesurer la ressemblance : la similarité cosinus à essayer

On compare l’angle entre deux vecteurs : proche de 1 = même sens, proche de 0 = sans rapport, négatif = opposé. Formule : cos(A,B) = (A·B) / (‖A‖ × ‖B‖)

8. Les 3 pièges classiques

Piège 1 : « 0.82 = chat ».
Faux. Les dimensions sont distribuées : le sens vient de l’ensemble du vecteur, pas d’une case.
Piège 2 : « L’embedding est écrit à la main ».
Faux. Notre [0.9, 0.8, 0.7, 0.1] en PHP était fictif, uniquement pour montrer Texte ➜ Vecteur ➜ Comparaison. Les vraies valeurs (0.012, -0.084, 0.231…) sortent du modèle.
Piège 3 : « Un token = un mot ».
Faux. Un mot rare peut être coupé en plusieurs morceaux (voir l’outil de l’étape 2).

9. Le code côté PHP

Le modèle fait Texte ➜ vecteur. Votre code ne fait que la comparaison :

function cosine(array $a, array $b): float {
    $dot = $na = $nb = 0.0;
    foreach ($a as $i => $x) {
        $dot += $x * $b[$i];
        $na  += $x * $x;
        $nb  += $b[$i] * $b[$i];
    }
    return $dot / (sqrt($na) * sqrt($nb));
}

10. Testez-vous

À retenir : les nombres d’un vecteur sont le résultat des calculs d’un réseau de neurones dont les poids ont été appris pendant l’entraînement. Textes proches ➜ vecteurs proches ➜ cosinus élevé.
Token
Morceau de texte (mot ou fragment) traité par le modèle.
Embedding
Vecteur qui représente le sens d’un texte.
Poids / biais
Paramètres appris par le réseau pendant l’entraînement.
Similarité cosinus
Score entre -1 et 1 mesurant la ressemblance entre deux vecteurs.
