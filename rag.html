0. Transition : où se situe le RAG ?

Reprenons l'exemple fil rouge : un chatbot intelligent pour un centre de formation. Il combine 4 couches technologiques. Cliquez sur chacune.

🧩 1. Machine Learning
Classifier la question : inscription, prix, durée ou programme. Un modèle simple suffit souvent ici.
🧠 2. Deep Learning
Un modèle de langage entraîné comprend le sens de la question et produit son embedding.
🗄️ 3. PHP + MySQL
Votre code stocke les documents, compare les vecteurs (similarité cosinus) et récupère les passages utiles.
💬 4. RAG
Les passages retrouvés et la question sont envoyés à un modèle génératif, qui rédige la réponse finale.

1. Le chatbot PHP « sans IA générative »

Imaginons une base de données sur une formation Laravel :

$documents = [
    "La formation Laravel dure 40 heures.",
    "La formation comprend PHP, MVC, Eloquent et API REST.",
    "Le prix de la formation est de 500 DT."
];

L'utilisateur demande : « Combien coûte la formation Laravel ? ». PHP peut chercher une correspondance et afficher une phrase déjà écrite à l'avance.

🧑
Combien coûte la formation Laravel ?
🤖
Le prix de la formation est de 500 DT.
Limite : si l'utilisateur demande « C'est combien pour apprendre Laravel ? », une simple comparaison de mots peut échouer : aucun mot n'est identique. PHP recherche et compare, mais ne comprend pas et ne rédige pas une réponse nouvelle.

2. Comment fonctionne le RAG : le pipeline en 5 étapes

RAG = Retrieval-Augmented Generation, « génération augmentée de recherche ». On ajoute deux étapes autour du LLM pour qu'il connaisse vos documents.

  1. 📄Documents
    PDF, Word, fichiers texte, table MySQL : la matière brute de votre base de connaissances.
  2. 🔢Embeddings
    Un modèle IA transforme chaque texte en vecteur (liste de nombres) qui représente son sens.
  3. 🔍Recherche sémantique
    PHP compare le vecteur de la question aux vecteurs stockés et récupère les passages les plus proches.
  4. 🧠IA générative (LLM)
    Le modèle reçoit la question et les passages retrouvés, puis rédige une réponse.
  5. ✅Réponse à l'utilisateur
    Une phrase naturelle, fondée sur vos documents, pas sur une réponse toute faite.

3.A Transformer un texte en vecteur (embedding)

Le vecteur n'est pas inventé par PHP : il est calculé par un modèle IA, via une API.

$texte = "La formation Laravel dure 40 heures.";

// Le modèle IA transforme le texte
// en une liste de nombres (vecteur).
$embedding = getEmbedding($texte);

// Exemple pédagogique simplifié du résultat :
// $embedding = [0.25, 0.81, -0.12, 0.44];
// En pratique : des centaines ou des milliers de valeurs.

Voir un embedding se calculer à essayer

$texte = "La formation Laravel dure 40 heures.";
$embedding = getEmbedding($texte);

Ici, 4 valeurs fictives pour l'exemple. Un vrai modèle en produit des centaines.

On stocke ensuite le texte et son vecteur dans MySQL, une seule fois par document :

CREATE TABLE documents (
    id INT AUTO_INCREMENT PRIMARY KEY,
    contenu TEXT,
    embedding TEXT   -- vecteur enregistré en JSON, ex: [0.25,0.81,-0.12,0.44]
);

3.B Rechercher les passages pertinents avec PHP

On transforme la question en vecteur, puis on la compare à chaque vecteur enregistré grâce à la similarité cosinus.

$question  = "Quelle est la durée du cours Laravel ?";
$vQuestion = getEmbedding($question);

foreach ($documents as $document) {
    $score = cosineSimilarity($vQuestion, $document['embedding']);

    if ($score > 0.75) {
        echo $document['contenu'];
    }
}
getEmbedding() et cosineSimilarity() sont des fonctions à implémenter (ou à connecter à une API d'embedding). Le seuil 0.75 est illustratif : à ajuster selon le modèle et vos données.

Le calcul de cosineSimilarity() en PHP :

function cosineSimilarity(array $a, array $b): float {
    $dot = $normA = $normB = 0.0;
    foreach ($a as $i => $x) {
        $dot   += $x * $b[$i];
        $normA += $x * $x;
        $normB += $b[$i] * $b[$i];
    }
    return $dot / (sqrt($normA) * sqrt($normB));
}

Score > 0.75 (barre verte) : le passage est retenu et envoyé au LLM à l'étape suivante.

3.C Générer une réponse avec le modèle IA

Une fois les passages retrouvés, on les transmet au modèle génératif avec la question, dans un seul prompt :

$context = "
La formation Laravel dure 40 heures.
Elle comprend PHP, MVC, Eloquent et API REST.
";

// La fonction envoie le contexte et la question
// à une API de génération de texte.
$reponse = generateAnswer($question, $context);

echo $reponse;
// "La formation Laravel dure 40 heures. Elle couvre
//  PHP, MVC, Eloquent et les API REST."
generateAnswer() représente un appel à une API de génération de texte (le LLM), pas une fonction PHP native. Voici à quoi elle peut ressembler avec l'API Claude :
function generateAnswer(string $question, string $context): string {
    $prompt = "Contexte :\n{$context}\n\nQuestion : {$question}\n"
            . "Réponds uniquement à partir du contexte ci-dessus.";

    $ch = curl_init('https://api.anthropic.com/v1/messages');
    curl_setopt_array($ch, [
        CURLOPT_HTTPHEADER => [
            'content-type: application/json',
            'x-api-key: ' . getenv('API_KEY'),
            'anthropic-version: 2023-06-01'
        ],
        CURLOPT_POSTFIELDS => json_encode([
            'model'      => 'claude-sonnet-5',
            'max_tokens' => 300,
            'messages'   => [['role' => 'user', 'content' => $prompt]]
        ]),
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_POST => true
    ]);
    $data = json_decode(curl_exec($ch), true);
    return $data['content'][0]['text'];
}
Important : ne mettez jamais la clé API dans du code accessible au navigateur. Gardez generateAnswer() côté serveur, avec la clé dans une variable d'environnement.
