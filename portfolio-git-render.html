Créer le portfolio (HTML/CSS)

Un bon portfolio tient en cinq blocs. Pas besoin de plus pour commencer — la qualité prime sur la quantité de sections.

Pourquoi une structure HTML « sémantique » ?

Le code ci-dessous utilise des balises comme <header>, <nav>, <section> et <footer> plutôt que de simples <div> partout. Ce n'est pas un détail esthétique : ces balises indiquent le rôle de chaque bloc.

Deux conséquences concrètes : les moteurs de recherche comprennent mieux la page (meilleur référencement), et les lecteurs d'écran utilisés par les personnes malvoyantes peuvent naviguer directement d'une section à l'autre. Un site « pro » commence par un HTML propre, avant même le design.

Une base à copier

Créez deux fichiers, index.html et style.css, dans le même dossier.










Le trajet, en un coup d'œil


Vos fichiers voyagent de votre ordinateur jusqu'au navigateur de vos visiteurs, en trois relais. Voici à quoi sert chacun avant de les enchaîner :




Git — le suivi des versions
Un outil installé sur votre ordinateur qui enregistre l'historique de vos fichiers. Chaque « commit » est un point de sauvegarde nommé : vous pouvez toujours revenir en arrière.


GitHub — l'hébergement du code
Une copie de votre dépôt Git stockée en ligne. Elle sert de source unique et sauvegardée, et c'est elle que Render va lire pour publier le site.


Render — l'hébergement du site
Un service qui prend les fichiers de votre dépôt GitHub et les rend accessibles au public via une URL, avec HTTPS automatique.









Les étapes, en détail




1 · Structurer les fichiers HTML/CSS
Un fichier index.html à la racine (obligatoire), un style.css, et un dossier images/ si besoin. Ouvrez index.html dans le navigateur pour le tester avant d'aller plus loin.



2 · Initialiser Git en local
Créez un dépôt Git qui suit l'historique de vos fichiers.


git init
git add .
git commit -m "Premier commit"


Ce que fait chaque ligne : git init crée le dépôt ; git add . sélectionne tous les fichiers modifiés ; git commit enregistre un point de sauvegarde avec un message descriptif. Prenez l'habitude d'écrire des messages clairs — c'est ce qui rend un historique de code lisible par vous-même et par d'autres développeurs.





3 · Créer un dépôt sur GitHub
Sur github.com : « New repository » → nom (ex. mon-portfolio) → public. Puis reliez votre dépôt local :


git remote add origin https://github.com/VOTRE-COMPTE/mon-portfolio.git
git push -u origin main



4 · Créer un compte Render et relier GitHub
Sur render.com, connectez-vous avec GitHub. Cliquez « New + » → « Static Site » → sélectionnez votre dépôt mon-portfolio.



5 · Configurer le déploiement
Laissez Build Command vide (rien à compiler en HTML/CSS pur). Mettez un point dans Publish Directory si vos fichiers sont à la racine :


Build Command : (laisser vide)
Publish Directory : .


Pourquoi laisser Build Command vide ? Cette option sert aux sites qui doivent être « compilés » avant publication (React, Vue…). Votre HTML/CSS est déjà prêt à être lu par un navigateur : aucune étape de construction n'est nécessaire.





6 · Déployer et récupérer l'URL
Render construit et publie automatiquement. Vous obtenez une URL du type https://mon-portfolio.onrender.com, avec HTTPS automatique et gratuit.


Le « s » de HTTPS signifie que les données échangées entre le visiteur et votre site sont chiffrées. C'est un signal de confiance basique attendu de tout site professionnel, et Render s'en charge sans configuration de votre part.





7 · Mettre à jour le site
Chaque nouveau commit poussé sur GitHub redéploie automatiquement le site sur Render.


git add .
git commit -m "Mise à jour du portfolio"
git push

Ce qui distingue un portfolio pro


Le code fonctionne ; ces détails font la différence entre « ça marche » et « ça fait sérieux ».




Balise meta description
Une phrase dans <head> qui s'affiche sous votre titre dans les résultats de recherche. Sans elle, Google en choisit une au hasard sur la page.


Favicon
La petite icône affichée dans l'onglet du navigateur. Son absence se remarque immédiatement et donne une impression d'inachevé.


Texte alternatif des images
L'attribut alt="…" décrit une image pour les lecteurs d'écran et s'affiche si l'image ne charge pas.


Poids des images
Des captures de projets non compressées ralentissent le chargement. Visez des fichiers JPEG ou WebP de quelques centaines de kilo-octets, pas plusieurs mégaoctets.


Contraste et lisibilité
Un texte gris clair sur fond blanc est difficile à lire. Gardez un contraste suffisant, surtout pour le texte principal.


Test sur mobile
Une bonne partie des visiteurs arrivera depuis un téléphone. Vérifiez que la navigation et les projets restent lisibles à l'étroit.





Conseils pour un portfolio qui donne envie de vous contacter


Un bon code ne suffit pas : ce que vous montrez et comment vous le racontez comptent autant.



Sur le contenu




Moins de projets, mieux présentés
3 à 5 projets solides valent mieux que 15 projets bâclés. Choisissez ceux qui montrent le mieux votre niveau actuel.


Racontez Problème → Solution → Résultat
Pour chaque projet : quel était le besoin, ce que vous avez fait, et ce que ça a changé (chiffre, retour utilisateur, apprentissage).


Un appel à l'action clair
Dites explicitement ce que vous voulez : « Me contacter », « Voir mon CV », « Discuter d'un projet ». Ne laissez pas le visiteur deviner.


Gardez-le à jour
Un projet vieux de 3 ans en avant montre une activité arrêtée. Retirez ou archivez ce qui ne vous représente plus.


Une touche personnelle
Une photo, une phrase sur votre parcours ou vos centres d'intérêt techniques humanisent la page sans la rendre bavarde.


Liez vos preuves sociales
GitHub, LinkedIn, un article que vous avez écrit, un témoignage court : chaque lien crédibilise ce que vous affirmez.





Sur la technique




Domaine personnalisé
Ajoutez votre propre nom de domaine dans les réglages du site sur Render, puis suivez les instructions DNS fournies.


Fichier .gitignore
Évite d'envoyer des fichiers temporaires générés par votre éditeur ou votre système d'exploitation.


Alternative : GitHub Pages
Tout aussi gratuite et encore plus directe : Settings → Pages → Deploy from a branch, sans compte supplémentaire.


Vérifiez les interfaces
Les boutons exacts sur github.com et render.com peuvent changer : gardez un œil sur leur documentation officielle.
