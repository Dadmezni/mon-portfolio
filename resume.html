03 Les mots-clés qui marchent le mieux par outil

Les mots-clés universels fonctionnent partout, mais chaque outil a ses tournures favorites. ChatGPT aime « step by step » et « act as » ; Claude réagit à « think deeply » et « cite sources » ; Gemini valorise « compare » et « with sources » ; Copilot attend « refactor » et « add types ».

04 Avant / Après : un prompt enrichi

Un prompt vague (« écris un article sur X ») donne une réponse vague. Ajouter rôle, public, longueur, structure, format transforme la sortie. C'est la même idée que la méthode PRECISE, illustrée en 1 exemple.

05 Pipeline RAG

On retrouve les passages utiles dans vos documents, puis un LLM rédige la réponse à partir d'eux. Pas d'invention : le modèle s'appuie sur vos sources.

06 Limites de l'IA

Un modèle peut inventer avec assurance (hallucination), reproduire des biais, ou exposer des données. La règle : l'IA assiste, l'humain valide.

⚖️ Outils IA — avantages, inconvénients, mots-clés

Pour chaque outil : ce qu'il fait bien, ses limites, et les mots-clés qui donnent les meilleurs résultats.

💬 ChatGPT

OpenAI · États-Unis
  • Très polyvalent : texte, code, images, voix
  • Écosystème riche (extensions, API, GPT)
  • Version gratuite aux fonctions limitées
  • Peut affirmer des erreurs avec assurance
Mots-clés : step by step act as format as
Idéal pour : l'usage polyvalent au quotidien.

🧠 Claude

Anthropic · États-Unis
  • Rédaction nuancée, code et longs documents
  • Bon suivi de consignes détaillées
  • Pas de génération d'images native
  • Limites d'usage sur l'offre gratuite
Mots-clés : think deeply reasoning cite sources
Idéal pour : rédaction, code, analyse de longs textes.

🔷 Gemini

Google · États-Unis
  • Intégré à Google Workspace et Android
  • Fort en multimodal (texte, image, audio)
  • Dépendance à l'écosystème Google
  • Confidentialité à vérifier (compte Google)
Mots-clés : with sources explain why compare
Idéal pour : les utilisateurs de Google Workspace.

📚 Perplexity

Perplexity AI · États-Unis
  • Réponses avec sources citées
  • Recherche web en temps réel
  • Dépend de sources web de qualité inégale
  • Moins adapté à la création longue
Mots-clés : cite sources recent news with links
Idéal pour : la recherche documentaire et la veille.

👨‍💻 GitHub Copilot / Cursor

Code · États-Unis
  • Complétion et refactorisation dans l'éditeur
  • Gain de temps sur le code répétitif
  • Le code généré doit être relu
  • Risque de dépendance
Mots-clés : refactor add types in the style of
Idéal pour : les développeurs au quotidien.

🎨 Midjourney / DALL·E

Images · États-Unis
  • Images artistiques de très haute qualité
  • Styles variés et cohérents
  • Contrôle précis limité (texte, détails)
  • Questions de droits sur les images générées
Mots-clés : cinematic photorealistic --ar 16:9
Idéal pour : illustration, direction artistique, concepts.

🌐 Développement web

PHP, HTML, Laravel, Bootstrap — 5 schémas pour voir comment une page prend vie.

07 PHP : échapper avant d'afficher

e() (ou htmlspecialchars) transforme les caractères dangereux en texte inoffensif. Toute donnée utilisateur doit passer par là avant affichage.

08 HTML sémantique

Des balises qui décrivent le sens (pas juste <div>) : meilleur SEO, meilleure accessibilité. Un <article> est un contenu autonome, réutilisable hors contexte.

09 Laravel — MVC

La route désigne le contrôleur, qui interroge le modèle (Eloquent), puis rend une vue Blade. Structure claire, sécurité intégrée, code maintenable.

10 Bootstrap — grille responsive

12 colonnes par ligne. col-md-6 = moitié à partir de 768 px, pleine largeur en dessous. Mobile-first avec des classes utilitaires prêtes à l'emploi.

11 Anatomie d'un prompt

Un bon prompt n'est pas une phrase vague. C'est une mini-spécification : rôle, contexte, tâche, format, évaluation. La méthode PRECISE.

🛠️ Outils & déploiement

Git, GitHub, Render — le trajet de vos fichiers jusqu'au navigateur du visiteur.

12 Git — historique de commits

Chaque commit est un point de sauvegarde nommé. On peut revenir en arrière, comparer, travailler en branches et fusionner.

13 GitHub — Pull Request

Une Pull Request propose des modifications, permet la revue par les pairs et la discussion, avant la fusion contrôlée dans main. C'est le cœur du travail collaboratif.

14 Render — déploiement auto

Render lit votre dépôt GitHub, publie le site en ~30 s et le redéploie à chaque git push. HTTPS automatique, URL publique accessible à tous.

💡 Conseils pour réussir vos candidatures

📄 Sur le CV et le portfolio

  • CV ATS-friendly : une seule colonne, texte simple (pas de tableau ni de photo), mots-clés de l'offre.
  • 3 projets chiffrés : « Application de gestion de tâches Laravel avec authentification, 100 % responsive, déployée sur Render ».
  • URL courte et propre : prenom-nom.com ou portfolio-prenom.onrender.com.
  • GitHub actif : au moins 1 commit par projet dans les 3 derniers mois.

💬 Sur l'entretien

  • Révisez vos propres projets : on vous demandera pourquoi vous avez utilisé telle solution.
  • Sachez expliquer simplement : « Un embedding, c'est… » avec vos mots. C'est ce qu'on attend d'un junior.
  • Montrez que vous apprenez en continu : citez vos lectures, votre dernier projet perso, une veille tech.
  • Posez des questions : équipe, stack, process. Cela montre votre intérêt réel.

🚀 Sur la candidature

  • Qualité > quantité : 3 candidatures personnalisées par jour battent 30 candidatures copiées-collées.
  • Lettre en 3 lignes : 1) Pourquoi cette entreprise. 2) Ce que vous apportez. 3) Ce que vous voulez apprendre.
  • Relance après 7 jours : un email poli sur LinkedIn double les chances d'avoir une réponse.
  • Postulez même si vous ne cochez pas tout : on ne coche jamais 100 %. 60–70 % suffit pour un junior.

🎯 Les pièges à éviter

  • Ne dites pas « j'apprends encore » : dites « j'ai déjà construit X et je continue sur Y ».
  • Ne montrez pas un tutoriel copié : les recruteurs repèrent les clones To-Do ou Netflix. Visez un projet à vous.
  • Ne mentez jamais sur vos compétences : l'entretien technique vous démasquera. Montrez ce que vous savez vraiment.
  • Ne postulez pas sans lien : CV + LinkedIn + GitHub + portfolio = 4 liens minimum sur la candidature.
