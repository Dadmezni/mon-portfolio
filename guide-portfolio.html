9Déployer sur Render

Mettre le portfolio en ligne automatiquement, à chaque push.

Render est une plateforme d'hébergement moderne qui se connecte à votre dépôt GitHub. Chaque git push sur main déclenche un nouveau déploiement, visible en direct dans l'onglet Events. Le site est en ligne en une trentaine de secondes.

Static Site, pas Web Service. Un portfolio HTML/CSS/Bootstrap ne nécessite aucun serveur : c'est un site statique. Choisissez le type Static Site. Un Web Service s'endort après 15 minutes d'inactivité et met environ 50 s à se réveiller — mauvais plan devant un recruteur.

Créer le service sur Render

  1. Allez sur render.com puis cliquez sur Sign in with GitHub.
  2. Autorisez Render à lire vos dépôts (vous pouvez restreindre l'accès au seul dépôt portfolio).
  3. Sur le Dashboard : New + → Static Site.
  4. Sélectionnez le dépôt portfolio, puis Connect.
  5. Remplissez le formulaire exactement comme ci-dessous :
  1. Cliquez sur Create Static Site.
  2. Attendez une minute. L'URL publique apparaît en haut du dashboard.
https://portfolio-prenom-nom.onrender.com
nom du service Render (choisi à l'étape 5)

Le cycle « push = redéploiement »

C'est le vrai intérêt de Render : plus rien à cliquer, plus rien à configurer. Modifiez un fichier, poussez, rechargez.

Pendant la séance, ouvrez l'onglet Events de Render dans un onglet voisin du terminal. Vos étudiants voient le déploiement se dérouler en direct : c'est bien plus parlant qu'un long discours.

Mettre à jour le site

Attendez 30 secondes, puis rechargez la page Render avec Ctrl + F5 (ou Cmd + Shift + R) pour contourner le cache du navigateur.

Bonus : le fichier render.yaml (Blueprint)

Pour aller plus loin — configurer Render depuis un fichier versionné

À la racine du dépôt, créez un fichier render.yaml. Au prochain branchement, Render lira ce fichier et configurera tout automatiquement. C'est de l'Infrastructure-as-Code : la configuration du déploiement est versionnée avec le code.

Preview Deployments — workflow professionnel

Quand vous poussez sur une branche autre que main et que vous ouvrez une Pull Request, Render crée une URL de préversion. On teste avant de fusionner.

Si ça ne marche pas

Render affiche « Build failed »

Vérifiez trois choses : Build Command vide, Publish Directory = ., et que index.html est bien à la racine du dépôt.

La page déployée est vide ou blanche

Le index.html est probablement dans un sous-dossier. Corrigez Publish Directory (ex. public ou src), puis Manual Deploy → Clear build cache & deploy.

Mon style.css ne charge pas en ligne (mais oui en local)

Les serveurs Linux sont sensibles à la casse : Style.css n'est pas égal à style.css. Vérifiez aussi les espaces et accents dans les noms de fichiers.

J'ai poussé mais rien ne change en ligne

Ouvrez l'onglet Events de Render : le déploiement est-il terminé ? Puis rechargez avec Ctrl + F5 pour vider le cache du navigateur.

Render redemande de se connecter à GitHub

Rendez-vous dans Account Settings → GitHub → Configure account. Vérifiez que le dépôt portfolio est bien dans la liste autorisée.

🎯 À vous de jouerFaites un commit avec une faute de frappe volontaire dans un titre, poussez, observez Render redéployer dans l'onglet Events, puis corrigez la faute et poussez à nouveau. C'est exactement le cycle de travail quotidien d'un développeur.

10Publier avec GitHub Pages (alternative)

Obtenir une seconde URL publique, hébergée par GitHub.

GitHub Pages est une alternative gratuite à Render. Utile comme sauvegarde, ou si vous préférez une URL en github.io. Cette étape est facultative si Render fonctionne déjà.

  1. Dans le dépôt : Settings.
  2. Menu de gauche : Pages.
  3. Source : Deploy from a branch.
  4. Branch : main, dossier / (root), puis Save.
  5. Attendez 1 à 3 minutes et actualisez : l'URL apparaît.
Erreur 404 ? Vérifiez que le dépôt est public et que index.html est bien à la racine.

11Projet final et vérification

Rendre un portfolio complet.

  • Toutes les sections sont présentes et personnalisées.
  • Au moins 3 projets en cartes, avec liens.
  • Images avec alt, burger testé, liens testés.
  • Au moins 8 commits, messages clairs.
  • Dépôt public, README complet avec l'URL de démo.
  • Render actif avec URL fonctionnelle.
  • (Bonus) GitHub Pages actif en parallèle.
